# План аудита «AlemTaxi» 0.2 (UC-01)

## 1. Цель
Определить, соответствует ли версия 0.2 (после ЛР №8) критериям приёмки и можно ли развернуть её для пилотного запуска в парке такси.

## 2. Область
Репозиторий https://github.com/yedilzhan/AlemTaxi, ветка main, коммит 7d667bd.
Входит: модули tariffs, drivers, rides, настройки, зависимости, docs/, история Git.
Не входит: хостинг и сервер (их нет), нагрузочное тестирование, админ-панель Django, вход по SMS и настоящий платёжный шлюз (не реализованы, шлюз — заглушка).

## 3. Критерии
- ISO/IEC 25010:2023 — характеристики качества;
- ТЗ, UC-01 с исключениями, БП-01…БП-05, контракт API, таблица трассировки (docs/lab7-report.md);
- критерии окончания из docs/test-plan.md: все тесты проходят, ruff без ошибок, покрытие ветвей слоя логики не ниже 90 %;
- контрольный список развёртывания Django (`manage.py check --deploy`); соглашение Conventional Commits.

## 4. Методы
Анализ документов; инструменты (тесты, ruff, radon, coverage с ветвями, bandit, pip-audit, check --deploy, tools/trace_check.py); функциональный и физический аудит конфигурации на чистом клоне; интервью (3 вопроса); выборка: 3 строки трассировки (БП-01, БП-04, БП-05), 3 закрытых Issues (если есть), последние 20 коммитов.

## 5. Аудиторы и роли
Руководитель аудита и аудитор — Наги Едильжан. Аудируемая сторона — тот же автор проекта.
**Независимость не обеспечена:** соседняя команда не назначена, поэтому аудит выполнен как самоаудит. Это ограничение указано в отчёте. Вступительная и заключительная встречи не проводились (аудитор и аудируемый — одно лицо).

## 6. График
Неделя 14: чек-лист (до сбора свидетельств), сбор свидетельств, FCA и PCA, отчёт и Issues. Неделя 15: корректирующие действия, повторная проверка.

- самоаудит снижает беспристрастность: вывод опирается только на воспроизводимые свидетельства;

- процесс проверяется выборочно.
