## «5 почему» для НС-1
1. Почему ключ и DEBUG=True в репозитории? — settings.py остался с ключом-заглушкой и режимом разработки с ЛР №6.
2. Почему их не заменили? — Проект запускали только локально, ничего не ломалось.
3. Почему не заметили в ЛР №7–8? — Тесты проверяют логику, а не настройки; безопасность в плане тестирования записана в «не тестируем».
4. Почему нет другой проверки? — Перед слиянием в main запускают только test и ruff.
5. Первопричина: в процессе разработки нет ни правила «секреты — только из окружения», ни автоматической проверки безопасности.

## Принятые риски и предупредительные действия
Принятый риск: предупреждения check --deploy W005 (SECURE_HSTS_INCLUDE_SUBDOMAINS) и W021 (SECURE_HSTS_PRELOAD) оставлены осознанно: HSTS для поддоменов и список preload практически необратимы, а домен сервиса пока неизвестен. Предупредительное действие: git grep по secret, password, token нашёл только DECLINED_TOKEN в rides/gateway.py — тестовая метка, помечена # nosec B105.

## Побочный эффект коррекции НС-1
В режиме разработки ключ генерируется заново при каждом запуске, поэтому после перезапуска сервера вход в админ-панель сбрасывается. В рабочем режиме (DJANGO_DEBUG=0) без DJANGO_SECRET_KEY проект не запускается.
