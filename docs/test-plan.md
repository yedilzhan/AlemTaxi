# План тестирования «AlemTaxi», версия 0.2 (UC-01)

## 1. Объект тестирования
Сценарий UC-01 «Заказ такси»: поиск водителей, создание заказа, оплата, отмена; исключения 5а, 5б, 7а. Модули tariffs, drivers, rides, ветка main после ЛР №7 (с оплатой и отменой).

## 2. Что тестируем
БП-01 (зона обслуживания), БП-02 (отмена до оплаты), БП-03 (стоимость), БП-04 (одна активная поездка), БП-05 (10 минут на оплату); формат телефона, координат и токена оплаты; переходы статусов поездки; коды ответов API по контракту (400, 402, 409, 410, 422); экраны Э-01…Э-04.

## 3. Что не тестируем и почему
- вход по SMS и настоящий платёжный шлюз — не реализованы (шлюз — учебная заглушка);
- нагрузка и безопасность — вне рамок учебной итерации (CSRF для API отключён осознанно);
- админ-панель Django — стандартный код фреймворка.

## 4. Уровни и методы
| Уровень | Метод | Инструмент |
|---|---|---|
| Модульный | Чёрный ящик: классы, границы, таблица решений, переходы состояний | Django TestCase |
| Модульный | Белый ящик: покрытие ветвей | coverage.py (branch) |
| Интеграционный | Сверху вниз с заглушками | unittest.mock |
| Системный | Ручные тест-кейсы, кросс-тестирование | браузер, GitHub Issues |

## 5. Среда
Windows, Python 3.13, Django 5.2, SQLite, браузер Edge. Данные — фикстура demo.json.

## 6. Критерии входа
Проект запускается по README, тесты ЛР №7 проходят, установлен coverage.

## 7. Критерии окончания
- все автоматические тесты проходят, `ruff check .` — без ошибок;
- покрытие ветвей слоя логики (`*/services.py`) не ниже 90 %;
- каждая строка таблицы трассировки проверена хотя бы одним тестом;
- нет открытых дефектов серьёзности «Критическая» и «Высокая».
